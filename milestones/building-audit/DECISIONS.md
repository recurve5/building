# Decisions — building-audit

| # | Decision | Rationale | Date |
|---|----------|-----------|------|
| 1 | Git attribution uses commit convention: `[TASK_ID] message` | Option A from the brief. Enables per-task Scope Creep detection. Missing prefix is itself a finding. | 2026-04-13 |
| 2 | Ground truth is an open item | Josh captures it in parallel. Tool validated against it when complete. | 2026-04-13 |
| 3 | Layer 2 LLM: Anthropic API, Sonnet tier | Cost-effective for focused judgment. Each check stays under 8K input tokens. | 2026-04-13 |
| 4 | Minimal runtime dependencies | npm packages fine. No external binaries. Exception: gitleaks optional. | 2026-04-13 |
| 5 | Report format is a contract | JSON schema is stable. Adding fields non-breaking. Removing/renaming breaking. | 2026-04-13 |
| 6 | gitleaks is optional, not required | Requiring a Go binary violates Decision 4. Falls back to built-in patterns when absent. Report notes degradation. | 2026-04-13 |
| 7 | Layer 2 checks skip LLM when zero candidates found | Cost proportional to risk, not fixed per run. | 2026-04-13 |
| 8 | Parse errors are reported, not fatal | Malformed task files produce parse_errors entries, not crashes. | 2026-04-13 |
| 9 | Exit codes: 0=clean, 1=critical findings, 2=tool error | Enables scripting and future pipeline integration without parsing JSON. | 2026-04-13 |
| 10 | Defer gitleaks integration to v2 | Built-in secret patterns are sufficient for v1. Removes subprocess command injection risk. Josh can run gitleaks manually. Architecture preserves upgrade path via SecretDetector interface. | 2026-04-13 |
| 11 | Per-check token limits (default 8K, max 16K) | Global 8K cap insufficient for Performance Critical Path and Refactoring Signals. Per-check limits maintain cost control for simple checks while giving complex checks sufficient context. Token usage visible in report. | 2026-04-13 |
| 12 | Rename Fluidity to `react-fluidity` | Check is React-specific. Silent clean on non-React projects is silent degradation (Decision 20). Reports `skipped` with reason when no React patterns detected. | 2026-04-13 |
| 13 | Coverage map included in PRD and report | 13 of 19 failure modes covered (11 fully, 2 partially). 6 uncovered modes are process/design failures with no artifact evidence. Report includes the map so the user knows what is and isn't checked. | 2026-04-13 |
| 14 | Confidence Bluff scoped to static verification | File existence, code structure, git diffs verified mechanically. Test result claims flagged as "unverifiable by static analysis" (warning severity). Test result files parsed if present in standard formats. | 2026-04-13 |
| 15 | AST parsing runs once in scanner, not per-check | Single-pass analysis stored in ProjectContext.sourceFiles. Checks consume pre-analyzed data. Scanner and runner log timing per phase/check. Enforces 30-second mechanical budget. | 2026-04-13 |
| 16 | Legacy projects: auto-detect missing commit convention | When >90% of commits lack `[TASK_ID]` prefixes, report a single info-level note instead of warning on every commit. Prevents noise on projects built before the convention. | 2026-04-13 |
| 17 | No task files: task-dependent checks report `skipped` | When zero task files found, log message and run task-independent checks only. Task-dependent checks report `skipped` with reason. | 2026-04-13 |
| 18 | Milestone git scoping via task ID filtering | Scanner identifies task IDs in milestone's `tasks/` directory, filters gitLog to matching commits plus unattributed commits touching milestone directory files. Limitation: cross-milestone shared code not included. Recommend running without --milestone for full coverage. | 2026-04-13 |
| 19 | Legacy projects use `--convention-start <hash>` flag | Replaces the 90% auto-detection threshold (Decision 16). Josh specifies the commit where the `[TASK_ID]` convention was adopted. Commits before that hash are excluded from attribution checks. Precise, not heuristic. | 2026-04-13 |
| 20 | Top-3 summary annotates cross-check correlations | When findings from different checks point at the same task or file, the top-3 summary notes the correlation. No separate compound findings section — just annotations on existing top-3 entries. | 2026-04-13 |
| 21 | Assertion patterns in external JSON config | Test Cheat loads assertion strength classifications from `assertion-patterns.json`. New matchers can be added without code changes. Prevents silent false negatives as the testing ecosystem evolves. | 2026-04-13 |
| 22 | Layer 2 dogfooded manually via Claude Code session, not API | M1 validation ran the seven Layer 2 prompts through this session against `~/building` rather than spending API tokens. Validates the prompts, candidate-finding logic, and judgment shape. Does not validate the SDK plumbing (token tracking, structured response parsing, retry, redact-before-send). That gap closes with M2's orchestrator (which can drive Claude Code sessions) or a single paid `--full` run. | 2026-04-29 |
| 23 | clean-slate-bias runs in mechanical mode without LLM | The check has two phases: candidate finding (mechanical, deterministic) and LLM confirmation (judgment). For per-task gating, the candidate-finding output is sufficient — agent or human reads colliding pairs and decides. Skips the LLM entirely in `--mechanical` mode. Keeps Layer 2 LLM confirmation for `--full` audits at milestone close. Closes the prevention gap surfaced when M1 dogfooded itself. | 2026-04-29 |
| 24 | Defer loadAssertionPatterns dedup | Same-named function exists in `analyzers/typescript-analyzer.ts` and `checks/layer1/test-cheat.ts`, each loading its own `assertion-patterns.json`. The two JSON files have drifted (analyzer has the richer set). Reconciliation requires care to avoid breaking test-cheat behavior. Deferred to a separate surgical task. | 2026-04-29 |

## Notes

Stress tests are tagged with `describe.concurrent` or a `@stress` marker so they can run on a longer timeout without slowing the fast test suite. They should be runnable separately: `npm test -- --grep stress`.

STRESS-003 (crash simulation) uses `process.kill(process.pid, 'SIGKILL')` in a child process to simulate mid-write crashes. The test verifies that after the kill, the state.json on disk is either the new content (write completed before kill) or the old content (atomic rename hadn't happened yet). Never a partial write.

STRESS-006 verifies portability by scanning each hook script for command invocations and checking against the allowed list in D0-8. This is a static analysis test, not a runtime test in a minimal environment.

The quality bar verification (criteria 8-10) is this task's primary contribution beyond stress testing. Per CLAUDE.md conventions, at least one task must close the quality bar loop. This is that task. Criterion 10 (PRD walkthrough executable) means: `/build --bootstrap` produces the documented output, `/build <brief>` starts a run, `/build --status` shows state, and the morning-after is generated at the documented path.
